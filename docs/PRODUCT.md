> **版本**：v1.0 · 2026-09-03  
> **客戶**：I.T 時裝零售（香港）

## 1. 產品定位

### 1.1 一句話

用 **店內視頻 AI（一見）** 看懂客流與服務現場，用 **IFMP** 做成可營運的看板與規則，再接 **排班 / 調度 /（選）IoT / POS**，幫 I.T **降本、增收、提服務質量**。

### 1.2 三目標（成功標準）

| 目標 | 產品如何貢獻 | 可驗證指標（試點後） |
|------|--------------|----------------------|
| **降本** | 減少過配人力；可選客流聯動節能 | 過配時段佔比 ↓；（選）電費/度數 ↓ |
| **增收** | 提升進店機會與熱區轉化動作 | 進店率 ↑；高停留區動作落地次數 |
| **提服務** | ≥2 分鐘無人服務可發現、可調度、可複盤 | 服務缺口次數/時長 ↓；VL 確認率 |

### 1.3 非目標（本階段不做）

- 不做會員人臉識別 / 隱私敏感的「認識誰是誰」
- 不承諾直接控制商場中央空調（無控制權則只監測）
- 不一次上全港所有門店（先 1 店試點）
- 本階段不標死報價數字（套餐結構見 §6）

## 2. 用戶與場景

| 角色 | 主要使用場景 |
|------|----------------|
| **店長** | 看今日缺口、調人、對排班；週會用回放教練 |
| **區域/營運** | 多店對標、進店率、人手健康度 |
| **IT / 物業** | 攝像頭、邊緣盒、Webhook、權限 |
| **HKIT 實施** | 標定畫線、ROI、工服庫、規則閾值 |

**現場約束（已確認）**

- 入口：玻璃門  
- 攝像頭：可利舊；有平面圖  
- 部署：一見邊緣盒；HKIT 為一見代理  
- 整合：IFMP Webhook；已有 VL/LLM 鏈路  
- 服務缺口閾值：**2 分鐘**  
- 人員：工服為主，可結合排班  
- 區域：貨架區、試衣間、收銀台

## 3. 產品架構

```
現場攝像頭 → 一見邊緣盒（感知）
                ↓ Webhook 事件
              IFMP（規則 + 看板 + VL 複核 + 告警）
                ↓
         行動層：排班建議 / 即時調度 / 服務教練
                ↓（選）
         POS 閉環 · IoT 節能
```

| 層 | 負責 | 不做 |
|----|------|------|
| **一見** | 檢測、追蹤、畫線、工服、區域停留、推事件 | 多店經營決策 UI |
| **IFMP** | 聚合、規則、看板、告警、複核、排班建議 | 替一見做底層視覺算法 |
| **行動/IoT/POS** | 調度、節能聯動、轉化歸因 | 無控制權時硬控設備 |

## 4. 功能範圍（按套餐）

### 4.1 套餐 A — 看見（MVP，Demo 已具備骨架）

對應五大需求：

| ID | 功能 | 說明 | 優先 |
|----|------|------|------|
| F1 | 店面客流 | 過店 / 進店 / 未進店 / 進店率；小時趨勢；事件表 | P0 |
| F2 | 店內動線 | 平面熱力、區域停留、動線 Top | P0 |
| F3 | 人員分類 | 員工 / 顧客 / 路人 | P0 |
| F4 | 員工監控 | 分時段在店人數；排班對照（讀） | P0 |
| F5 | 服務缺口 | ≥2min 無人服務；不足/過多%；面積；VL 狀態 | P0 |
| F6 | 總覽看板 | 5 KPI + 曲線 + 熱力縮略 + 告警 | P0 |
| F7 | 全局篩選 | 門店 / 日期 / 時段 / 對比 | P0 |
| F8 | 設定（只讀 Demo） | 門店、區域、攝像頭、規則展示 | P1 |

### 4.2 套餐 B — 行動（下一階段主推開發）

| ID | 功能 | 說明 | 優先 |
|----|------|------|------|
| F9 | 排班建議 | 依歷史客流建議每小時應到人數；店長可調 | P0 |
| F10 | 即時調度 | 缺口事件推送「需支援區域」給店長/員工端（先 Web/模擬） | P0 |
| F11 | 服務教練 | 缺口列表 + 片段佔位 + VL 摘要；週會篩選 | P1 |
| F12 | 首次接觸 SLA | 可配置目標秒數（默認 90s），與缺口同源 | P1 |

### 4.3 套餐 C — 閉環（路線圖）

| ID | 功能 | 說明 | 優先 |
|----|------|------|------|
| F13 | POS/會員對接 | 進店→購買漏斗；熱區轉化 | P2 |
| F14 | 多店對標 | 進店率、缺口率、人效橫比 | P2 |

### 4.4 套餐 D — 綠色選配

| ID | 功能 | 說明 | 優先 |
|----|------|------|------|
| F15 | 環境監測 | 溫濕、電表讀數進 IFMP | P2 → **Demo 已加 `/retail/energy`** |
| F16 | 客流聯動控制 | 有控制權才做空調/燈光策略 | P2（條件；頁面展示規則，執行待硬體） |

## 7. 數據與集成

### 7.1 一見 → IFMP Webhook（已定事件）

| event_type | 用途 |
|------------|------|
| `footfall_crossing` | 過店/進/離 |
| `zone_enter` / `zone_exit` | 停留與動線 |
| `zone_occupancy` | 人手與人效 |
| `service_gap` | 缺口告警 |
| `role_reclassified` | 工服/排班修正 |

端點：`POST /api/retail/webhook/yijian`  
詳見 Spec §4。

### 7.2 規則引擎（產品默認）

```yaml
service_gap:
  dwell_threshold_sec: 120
  staff_proximity_m: 3
staffing:
  overstaff_multiplier: 1.5
sla:
  first_contact_sec: 90   # B 套餐
```

區域標準人數：設定可配；Demo 默認各區 min_staff=1。

### 7.3 數據源切換

```
VITE_DATA_SOURCE=mock | live
```

前端頁面不因切換改組件，只換 API base。
